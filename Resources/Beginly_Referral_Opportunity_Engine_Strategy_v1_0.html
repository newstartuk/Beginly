1. Executive Summary

Referral links are not the product. The product feature is a trust-safe Opportunity Engine that helps newcomers discover timely settlement actions, savings, safety checks, partner options and package support.

The uploaded workbook is commercially valuable, but it should not be implemented as a direct affiliate-link dump. The strategic implementation should be a broader Beginly Engagement & Opportunity Engine. This engine should combine:

  • Opportunity Scanner - a personalised feed of useful settlement opportunities based on profile, journey stage, checklist status and preferences.
  • Contextual referral-in-content - relevant partner/referral blocks inside guides, task details, budget pages and support flows.
  • Notification system - opt-in in-app, email and device push reminders that bring users back before they forget important settlement steps.
  • Geo/radius-sensitive layer - optional, consent-led location relevance for campus, transport, health, accommodation and local setup prompts.
  • Package notification engine - value-triggered prompts for free, plus, premium, support, trial, renewal and sponsored access packages.
  • Governance layer - admin review, source verification, disclosure, consent, frequency capping and compliance controls.
Recommended positioning: Beginly should not sell links. Beginly should surface timely settlement opportunities. Where a trusted partner link genuinely helps, it can be clearly disclosed and used.

Executive verdict

QuestionVerdict
Should the spreadsheet be used?Yes, but as a structured Opportunity Registry, not as a live affiliate-link sheet.
Should Opportunity Scanner be the only monetisation surface?No. It should be the brain, while content, notifications, Nia, budget pages, task details and package prompts are distribution surfaces.
Should geo-location be used?Yes, later, only with explicit opt-in, clear user control and a service-first purpose.
Should package/subscription notifications be used?Yes, but as value-triggered package prompts, not aggressive sales notifications.
What should be built first?Opportunity Registry, disclosure components, consent preferences, in-app scanner, contextual content blocks and admin review workflow.

3. Strategic Reframing: From Referral List to Opportunity Engine

The strongest strategic move is to make the referral layer behave like part of the user journey, not like advertising pasted onto the product.

Strategic reframing: The workbook becomes Beginly's Opportunity Registry. The app uses this registry to power Opportunity Scanner, content blocks, notifications, Nia explanations and package prompts.

Five opportunity types

TypeExampleRevenue?Trust note
OfficialGOV.UK, NHS, university, council or UKCISA guidance.NoShould be prioritised for sensitive topics.
SafetyHousing scam warning, job scam warning, document protection reminder.NoMust never be mixed with aggressive sales.
SavingsRailcard, student discount, SIM comparison education, budget review.SometimesFrame as things to compare, not as guaranteed savings.
PartnerVerified accommodation, airport pickup, student support or local service.PossiblyRequires partner vetting and complaint tracking.
ReferralSIM, money transfer, banking comparison, insurance, utilities, broadband.YesRequires clear disclosure and consent where tracking is used.
PackageBeginly Plus, premium reminders, support sessions, sponsored access.YesMust be value-triggered and transparent.

Ranking logic

The scanner should rank by user value and trust fit before revenue. Revenue must be a secondary internal signal.

  1. User safety
  2. Current settlement need
  3. Journey stage relevance
  4. Trust/source confidence
  5. User value score
  6. Compliance simplicity
  7. Revenue potential
Do not rank by commission. The product must not feel like a disguised affiliate site. This is central to preserving Beginly's trust position.

The engine requires strong consent and disclosure architecture because it combines affiliate links, marketing notifications, cookies/tracking, location and subscriptions.

Disclosure language

Universal affiliate disclosure

Partner disclosure: Some links may be partner links. Beginly may receive a referral fee if you use them. This does not make the provider official or guaranteed. You should compare options and check provider terms before choosing.

Financial/banking-safe wording

Beginly does not recommend financial products. We provide general things to compare and signpost official provider information. Check your own circumstances and provider terms before applying.

Package wording

Beginly Plus renews monthly unless cancelled. You can cancel from Settings. Free roadmap access remains available unless clearly stated otherwise.

Beginly should not allow developers or content editors to paste referral links directly into pages without review. The Opportunity Registry should have a controlled approval workflow.

Required admin checks before going live

  • Provider programme verified.
  • Application approved or direct relationship confirmed.
  • Tracking link generated and tested.
  • Disclosure text attached.
  • Cookie/tracking consent requirement defined.
  • Risk level assigned.
  • Source URL recorded.
  • Last verified date recorded.
  • Page/task/guide placement approved.

  • Fallback/free/official option provided where appropriate.
  • Owner and next review date assigned.

Opportunity engine pseudo-code

export function scoreOpportunity(user, opportunity, context) {
  let score = 0;
  score += opportunity.user_value_score * 6;       // 30 max
  score += stageMatches(user.stage, opportunity) ? 20 : 0;
  score += opportunity.trust_score * 4;           // 20 max
  score += complianceWeight(opportunity);         // 15 max
  score += opportunity.revenue_score * 2;         // 10 max
  score += implementationEase(opportunity);       // 5 max

  if (!hasRequiredConsent(user, opportunity, context.channel)) return null;
  if (!isWithinFrequencyCap(user, opportunity, context.channel)) return null;
  if (opportunity.status !== 'live' && opportunity.status !== 'approved') return null;
  if (isSensitiveSuppressed(context)) return null;

  return score;
}

export function getRecommendedOpportunities(user, context) {
  return opportunities
    .filter(o => triggerMatches(user, o, context))
    .map(o => ({ opportunity: o, score: scoreOpportunity(user, o, context) }))
    .filter(x => x.score !== null)
    .sort((a, b) => b.score - a.score)
    .slice(0, 5);
}

Acceptance criteria

  • Every live opportunity has a verified source/programme record and next review date.
  • Every referral/partner block has visible disclosure near the CTA.
  • Financial, insurance, housing and immigration-adjacent content avoids advice, guarantees and rankings.
  • Users can save, dismiss, hide category and understand why an opportunity was shown.
  • Marketing push/email notifications are not sent without separate opt-in.
  • Location-aware alerts are not enabled by default.
  • Package prompts always show free alternative, price/terms where relevant, and cancellation/renewal information.
  • Admin can pause an opportunity globally without code deployment.
  • Analytics distinguish helpful engagement from aggressive conversion chasing.
  • High-risk categories require compliance review before publication.
