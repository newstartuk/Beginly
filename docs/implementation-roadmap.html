01

Data layer reconciliation

Blocking — next

The newly merged API routes reference tables that likely don't exist in the live Supabase project yet.

  • Audit every new API route (household, journey, opportunities, products, billing, admin) against the actual deployed schema
  • Write and run migrations for missing tables — entitlements, billing_events, journey_tasks, household/opportunity/product tables
  • Verify RLS policies on every new table before any route goes live
  • Smoke-test each new route against a real (or local) Supabase instance, not just a clean TypeScript compile
Why this blocks everything below: the new pages render and compile today, but without real tables behind them, Journey / Household / Opportunities / Products will fail at runtime the moment a user interacts past the static shell.

Scope note

This roadmap replaces ROADMAP.md at the project root, which was written in June 2026 and predates the brand rebuild and the v1.3 platform merge — several of its P0 items (no landing page, no onboarding gate) are already resolved.

It does not touch the pre-existing strategy documents in the project root (BEGINLY_STRATEGIC_COMPENDIUM.md, the Sir Edmund Hale briefs, the beginly_*_roadmap.html files) — those are business-strategy and naming exploration, not implementation status, and rewriting them wasn't part of this pass.
